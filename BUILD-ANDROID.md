# Building the Android APK (release)

This is the operational doc for producing a signed `app-universal-release.apk`
for fGw / Powder Keg compost-marketplace. Run the **One-time keystore setup**
section once, then run **Per-release build** for every alpha/beta cut.

This file is referenced from
[`.wiki/output/projects/alpha-bundle/plan-alpha-bundle-2026-05-22.md`](./.wiki/output/projects/alpha-bundle/plan-alpha-bundle-2026-05-22.md)
(see Phase 4) and pairs with the nginx config at
[`.wiki/output/projects/alpha-bundle/nginx.fgw.conf.md`](./.wiki/output/projects/alpha-bundle/nginx.fgw.conf.md).

## Prerequisites

- **JDK 17+**. Verify with `java --version`. Tauri Android requires it.
- **Android SDK** installed and `ANDROID_HOME` exported. Tauri's
  `pnpm tauri android init` (already run in this repo — `src-tauri/gen/android/`
  exists) handles most of the SDK wiring.
- The repo cloned and `pnpm install` complete.
- `apksigner` and `adb` on `PATH` (both ship with the Android `build-tools`
  and `platform-tools` packages).

## One-time keystore setup

Do this once, before the first signed release. Subsequent releases reuse the
same keystore.

1. **Generate the keystore.** Pick a permanent location *outside* the repo:

   ```sh
   keytool -genkey -v -keystore ~/secrets/fgw-android.keystore \
     -alias fgw -keyalg RSA -keysize 4096 -validity 25000
   ```

   The 25,000-day validity is conventional for Android release signing.
   `keytool` will prompt for a keystore password, key password, and a
   distinguished name (CN, OU, O, L, S, C). Use the chapter's name; the DN
   is visible in the APK certificate but is not used for trust decisions.

2. **Move the `.keystore` file to a permanent, gitignored location** (e.g.
   `~/secrets/fgw-android.keystore`). Do not place it inside the repo.

3. **Back up the keystore to two offsite locations.** This is the single
   irreversible step in the entire alpha pipeline. Suggested:
   - Encrypted attachment in a password manager (1Password, Bitwarden).
   - Encrypted USB stick stored offsite.

   **If you lose the keystore, you cannot publish updates to the same
   Android package ID.** The next release would have to use a new package
   ID (`tech.virginiafreedom.compost2` or similar), which breaks in-place
   upgrades for every existing install — they'd have to uninstall and
   reinstall, losing all local data.

4. **Create `src-tauri/gen/android/keystore.properties`** by copying the
   template (which lives at the repo's `src-tauri/` root, outside the
   gitignored `src-tauri/gen/` tree so it can be committed):

   ```sh
   cp src-tauri/keystore.properties.template \
      src-tauri/gen/android/keystore.properties
   ```

   Fill in the four values (`storeFile`, `storePassword`, `keyAlias`,
   `keyPassword`). Then confirm `git status` does NOT list the file —
   the broad `src-tauri/gen/` ignore rule plus the explicit
   `src-tauri/gen/android/keystore.properties` line in `.gitignore`
   both cover it. If it shows up, stop and fix the gitignore before
   proceeding.

## Per-release build

Run from the repo root.

1. `pnpm install` (skip if you've installed recently).
2. Build the APK:

   ```sh
   pnpm tauri android build --apk
   ```

   Output lands at
   `src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk`.

3. Stage the artifact under `dist-mobile/` (create it if it doesn't exist):

   ```sh
   mkdir -p dist-mobile
   cp src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk \
      dist-mobile/fgw-0.1.0-alpha.1.apk
   ```

4. Verify signing:

   ```sh
   apksigner verify --print-certs dist-mobile/fgw-0.1.0-alpha.1.apk
   ```

   Output should print the certificate fingerprint (SHA-256). If you see
   "DOES NOT VERIFY" or no certs, your `keystore.properties` is misconfigured.

## Real-device smoke

1. Enable USB debugging on the test device (Settings → About phone → tap
   Build number 7 times → Settings → Developer options → USB debugging).
   Connect via USB and accept the RSA fingerprint prompt.
2. Install:

   ```sh
   adb install -r dist-mobile/fgw-0.1.0-alpha.1.apk
   ```

3. Open the app from the device launcher. Complete onboarding with a test
   nsec. Publish one listing. Confirm the membership poller fires (the
   device must be on a network that can reach `chat.virginiafreedom.tech`).
4. Verify Tauri plugins on Android: the notification permission prompt
   fires; the camera permission prompt fires when you tap "Scan QR" in
   the NIP-46 pairing flow. (SPEC-035 wired the iOS Info.plist;
   Android's manifest is auto-generated by Tauri's barcode-scanner plugin
   scaffold — verify it actually works on the real device.)

## Sideload deployment for the alpha

1. `rsync` the artifact to the chapter server:

   ```sh
   rsync -av dist-mobile/ root@<server>:/var/www/fgw.virginiafreedom.tech/downloads/
   ```

   The server is provisioned per
   [`.wiki/output/projects/alpha-bundle/nginx.fgw.conf.md`](./.wiki/output/projects/alpha-bundle/nginx.fgw.conf.md).

2. Testers install from
   `https://fgw.virginiafreedom.tech/downloads/fgw-0.1.0-alpha.1.apk`
   per the steps in `INSTALL.md` (Phase 5; not yet written at the time
   this doc was committed).

## Known issues

- **Tauri Android plugin maturity is uneven.** `notification`, `sql`,
  `stronghold`, and `barcode-scanner` all need device testing each
  release. If a plugin fails on a real device, document the failure in
  `INSTALL.md` "Known issues" and file a follow-up SPEC.
- **First-launch sideload UX on Android 14+.** The user must enable
  "Install unknown apps" per source app (Chrome / Firefox / etc.) before
  tapping the APK, plus dismiss a Play Protect warning. Documented in
  `INSTALL.md`.
- **Keystore is single-key today.** Multi-developer signing (e.g. one
  CI keystore + one human-developer keystore for emergency releases)
  requires a separate plan and likely Google Play's App Signing program.
- **`pnpm tauri android init` will overwrite `src-tauri/gen/android/app/build.gradle.kts`**
  and clobber the `keystoreProperties` + `signingConfigs.release` blocks
  added per this doc. The whole `src-tauri/gen/` tree is gitignored (it's
  treated as build-time scaffold), so a fresh clone has no signing
  config until those gradle edits are reapplied. Two ways to handle it:
  (a) keep a private patch / fork of the gradle changes and reapply
  after `tauri android init`, or (b) avoid re-running `tauri android
  init` once the keystore is wired (the existing `gen/android/` tree
  already has everything the CLI would scaffold). Option (b) is the
  recommended path until upstream Tauri ships first-class signing config.
